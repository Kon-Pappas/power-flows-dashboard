# Decisions log

Format: **what** · *why* · alternatives rejected. The log starts on 19 October 2026, the day the alignment of this dashboard with the other hub dashboards began (house style as in live-greekpower and BigHydro). Decisions marked *(existing)* record how the code already worked before that day. Items marked *(planned)* are decided but not yet in the code. Newest decisions last.

| # | Decision | Why / what was rejected |
|---|---|---|
| D01 | This repository follows the **hub house style** (shell, loading overlay, language, accent, modal) while keeping its own analyses: ISP vs SCADA, BG↔IT transit netting, daily and month-to-date cash position, completeness flags. It is handled in its own threads; documentation starts lean (`DECISIONS`, `KNOWN_ISSUES`, `ROADMAP`), with `ARCHITECTURE` / `DATA_DICTIONARY` / `METHODS` later | Same look and behaviour across the hub, one place to read why things are as they are. Follows live-greekpower D11 and D13. |
| D02 | The accent colour is **cyan** (`#22d3ee`, with 200/300/500 tints), defined in one place at the top of `index.html` (`window.ACCENT`, used by Tailwind as `acc-*`). One accent for the whole page, not one colour per tab. In batch 1 it is used by the loading overlay; the rest of the page follows *(planned, K02)* | Cyan is the colour assigned to Flows in BigHydro D23 (BESS emerald, Gas-Power blue, BigHydro violet; live-greekpower platinum, D09). |
| D03 | **Loading overlay** paced as in live-greekpower D47: all five steps visible from the start at half opacity; step 1 *Reading the data* follows the real download of the two files (`meta.json`, `historical_flows.json`) with a 650 ms minimum; steps 2–5 are one per tab, in tab order: each lights up, waits 20 ms, **draws its tab**, then its bar fills linearly in 350 ms and gets a ✓; *ready* stays 650 ms before a 0.5 s fade. Reduced-motion users get 120 / 200 / 200 ms. No percentage counter. If the data cannot be loaded the overlay stays, the spinner stops and a message asks the visitor to reload (same text as live). The second group is called *Building views*. To make one step per tab real, `renderCharts()` was split into `renderTotalsTab`, `renderHourlyTab`, `renderArbitrageTab` and `renderMTDView`; `renderCharts()` still calls all four when the date, month or language changes. The first tab's English label is corrected to *Daily ISP vs SCADA* | Before: each step animated before any work; steps 3 and 5 did nothing and step 4 drew all tabs at once, so the page froze after a ✓; rows popped in one by one; a 0–100% counter flickered; on a failed download the overlay vanished and left an empty page. Timings identical to live, so the hub feels the same everywhere; with four tabs instead of five the overlay ends ≈0.4 s earlier. Measured on 19 Oct 2026 (Playwright, 60 ms sampling): ✓ every 0.40–0.42 s, last ✓ at ≈3.0 s; reduced motion ≈1.3 s. Rejected: a dummy fifth step to match live's length; byte-level progress (GitHub Pages serves the file compressed, so the bar would pass 100%). |
| D04 | English by default; the visitor's choice is stored in the browser under the shared key `kp_lang` and used on the next visit | Follows live-greekpower D10 / BigHydro D24: all dashboards share one origin, so the language follows the visitor across the hub. |
| D05 | The update runs **only** through the external **cron-job.org**, daily at **07:02 Athens time**; the workflow has no `schedule:` block | The GitHub cron (04:17 UTC) also ran, so the fetch ran twice a day; GitHub's cron is late by 5–20 min; and 04:17 UTC moves to 06:17 Athens after 25 Oct. Follows live-greekpower D02. |
| D06 | `data/meta.json` holds `fetched` (time of the run) and `next_update` (next 07:02 Athens, computed with the time zone, so correct across daylight-saving changes). Its only writer is `update_flows.py`, after the data file was written successfully; the page shows both in Athens time and shows "–" if the file is missing | Before: the page showed the latest data date + a fixed 08:00 as *Last update* and the next day 08:00 as *Next*, neither of which was the real run time. Python computes, the page only shows (live-greekpower D16). |
| D07 | Tailwind is pinned to 3.4.17 (play CDN) | The accent palette (D02) is passed through `tailwind.config`, an API of the 3.x play CDN; a pinned version stops a library release from changing the page overnight (live-greekpower D21). Chart.js is not pinned yet (K01). |
| D08 | GitHub Actions: `actions/checkout@v5`, `actions/setup-python@v6` | The earlier versions run on Node.js 20, which GitHub is retiring (live-greekpower D26). |
| D09 | *(existing)* Pipeline rules: what cannot be found is written as `null`, never 0; the data file is read strictly (a corrupt file stops the run and nothing is written); writes are atomic (temporary file, then rename); a new fetch never replaces good SCADA, ISP or price data with an empty or shorter series; every run re-fetches the last five days, so late publications are picked up | A failed or partial download must not erase history. |
| D10 | *(existing)* Completeness: a day is complete when it has SCADA data and 24 plausible prices (no gaps, at most 12 zero hours) for Greece and for Bulgaria / Italy when flows to them exist. Incomplete days are marked ⚠ in the picker and with a badge, their cash flow is not shown, and they are excluded from the month-to-date figures with a list of the excluded dates | A cash figure built on missing prices or flows would look exact and be wrong. |
| D11 | *(existing)* Cash pricing: flows with Albania, North Macedonia and Turkey are priced at the Greek day-ahead price; flows with Bulgaria and Italy at the average of the Greek and the neighbour's price. Optional **BG↔IT transit netting**: in hours when Greece imports from one of the two and exports to the other, the shared volume is priced once, in the dominant direction; MWh figures never change, only the cash flow | Avoids counting energy that only crosses Greece twice in the cash position. |
| D12 | **Data colours** (20 Oct 2026): ISP (scheduled) is steel blue `#7896c0`; Turkey is pastel pink `#f9a8d4`; the Italian day-ahead price line is purple `#a855f7`, the same as Italy in the arbitrage chart (taken from `countryColors.IT`). SCADA orange, the other countries and the GR / BG price lines stay | ISP was cyan, the accent itself (D02), so the accent carried a data meaning. Steel blue sits in the slate family of the background and is the complement of SCADA's orange, so the pair separates at a glance without competing with Albania's or Greece's saturated blue. Turkey's teal was close to cyan; pink is used by no other element. Italy's price was yellow, the colour of imports and of transit hours; with purple Italy has one colour on every tab. Rejected for ISP: silver slate (reads as disabled, close to live-greekpower's platinum), blue-400 (close to Albania). Rejected for Turkey: lime (close to yellow), mint (close to the green ✓ and the BG price). Rejected for the Italian price: lavender (a second shade for Italy), white (the applied-price line in the arbitrage chart) |
| D13 | **Completeness is computed only in Python** (20 Oct 2026): `day_complete()` in `update_flows.py` writes `Flags.complete` for every day, recomputed over the whole history on every run, with the rule of D10. The page reads the flag | Before, Python wrote whether SCADA exists and the page checked the prices itself, so two places defined a "complete day". Python computes, the page only shows (live-greekpower D16). Checked on 141 days (1 Jun – 19 Oct 2026): identical result to the old page rule on every day. The old page rule stays only as a fallback for days without the flag (K10) |
| D14 | **Picker, status pill and accent, as in live-greekpower** (20 Oct 2026). One picker box (`pickerBox`): "Day:" on the first three tabs (one day shared by them), "Month:" on MTD; neutral look, accent on focus. Dates in the visitor's language ("12 Oct 2026", "October 2026"), today marked "(today)", incomplete days keep ⚠, the default is still the latest complete day; a language change keeps the selection. The completeness badge left the picker and became a pill next to Last / Next update (shape and tones of live's pill: green complete, orange incomplete), hidden on MTD. Accent (`acc`) everywhere it is decoration: title, breadcrumb hover, Last-update value, active tab (mobile and desktop, MTD no longer special), active GR \| EN with dark text, transit toggle, methodology icon, section titles and Short / Detailed switch; Next-update value light grey. Emerald stays only where it means something: complete data, positive cash, best MTD day, ✓. Transit marks (⇄, transit volumes, info line) are neutral grey / white | Same picker and header on every hub page; the accent carries no data meaning (live D22). Rejected for transit: yellow (already means imports) and cyan (the accent) |
| D15 | **Shell as in live-greekpower** (20 Oct 2026). Methodology modal: boxed X (9×9, border) and bordered Close button; Esc closes it; the page behind does not scroll while it is open; focus goes to the X on opening and back to the Methodology button on closing; thin scrollbar; `role="dialog"`. Footer separated by a rule (live D40). Header labels in sentence case ("Last update:", "Τελευταία ενημέρωση:"). Kept as Flows' own: the Short / Detailed switch, the title *Methodology & Assumptions* (the assumptions are the core of this page), and the short header labels on mobile | Same shell on every hub page. The short mobile labels read better than live's and are a candidate for the other pages (H02) |
| D16 | **Methodology links in context** (as live D40): the ⓘ next to the transit toggle is a button that opens the methodology, in its detailed form, at the transit item; the ⚠ notices (incomplete day, days excluded from MTD) end with "Methodology →", which opens it at the data-completeness item. Anchors are an optional third element of a methodology item (`m-transit`, `m-complete`) | Long explanations stay in the methodology; the page keeps one sentence. On mobile a `title` tooltip never shows, so the ⓘ had no effect there |
| D17 | **Greek page fully in Greek** (20 Oct 2026): country names come from the language texts (`countries`) in the arbitrage table and both arbitrage views, the ISP vs SCADA chart and the tooltips; chart legends of the arbitrage (single-country flow, applied price) and MTD charts are translated; price codes on the Greek page are ΕΛ / ΒΓ / ΙΤ (as in the "ΒΓ↔ΙΤ" toggle); methodology section titles follow the tab names (e.g. ΣΩΡΕΥΤΙΚΗ ΘΕΣΗ (MTD), ΠΕΡΙΟΡΙΣΜΟΙ). Units and the terms ISP, SCADA, MTD, arbitrage stay as they are | Was K12: a Greek visitor saw mixed languages. Country names are defined once per language instead of in three places |
